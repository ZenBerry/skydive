Skydive Agent Interface

This page is intended for AI agents. It describes how to read and modify Skydive spaces through a small JSON API backed by Netlify Functions.

Start by fetching the machine-readable manifest: GET /api/agent?manifest=1

Access

By default, no token is required. Give this page to an AI agent and it can discover the API, list spaces, read spaces, and apply edits.

If private mode is enabled later, agents should send: 

Authorization: Bearer <SKYDIVE_AGENT_TOKEN>

Private mode is optional: set SKYDIVE_AGENT_AUTH_MODE=token and SKYDIVE_AGENT_TOKEN in Netlify.

Core Workflow

  1. Fetch /api/agent?manifest=1 to discover capabilities and limits.
  2. Fetch /api/agent?spaces=1 to list known spaces.
  3. Fetch /api/agent?space=<slug> before editing a space.
  4. Send POST /api/agent with space, baseRevision, and a batch of ops.
  5. If the API returns 409, re-read the space and retry against the new revision.

Endpoints

Manifest GET /api/agent?manifest=1
List spaces GET /api/agent?spaces=1
Read a space GET /api/agent?space=<slug>
Apply edits POST /api/agent

State Shape

{
  "version": 1,
  "nodes": [
    {
      "kind": "text",
      "id": "node-1",
      "x": 0,
      "y": 0,
      "baseFontSize": 28,
      "createdBy": { "id": "user-id", "nickname": "CoffeeCup" },
      "text": "Hello",
      "html": "Hello"
    },
    {
      "kind": "command",
      "id": "node-2",
      "x": 120,
      "y": 80,
      "baseFontSize": 28,
      "commandId": "stw",
      "commandVersion": "1.0.0",
      "commandState": {}
    }
  ]
}

createdBy is optional and server-assigned from the active Skydive session. Space records likewise retain their initial createdBy user when one exists.

Batch Edit Example

POST /api/agent
Content-Type: application/json
Authorization: Bearer <SKYDIVE_AGENT_TOKEN>

{
  "space": "my-space",
  "baseRevision": 7,
  "ops": [
    {
      "op": "create_text_node",
      "id": "node-agent-note",
      "x": 0,
      "y": 0,
      "text": "A new agent-created thought"
    },
    {
      "op": "create_command_node",
      "id": "node-agent-stopwatch",
      "x": 0,
      "y": 90,
      "commandId": "stw",
      "commandVersion": "1.0.0",
      "commandState": { "running": false, "startedAt": null, "elapsedMs": 0 }
    },
    {
      "op": "align_nodes",
      "ids": ["node-agent-note", "node-agent-stopwatch"],
      "alignment": "left"
    }
  ]
}

Supported Ops

  • create_text_node: create a text node with text or trusted html.
  • create_command_node: create an instance of a registered command.
  • update_node: edit position, size, text/html, or command state.
  • move_node, resize_node, delete_node: targeted node edits.
  • align_nodes: align by left, right, center, top, bottom, or middle.
  • distribute_nodes: distribute horizontally or vertically.
  • link_text: wrap matching source text in a Skydive internal link to another node.
  • replace_state: replace the whole space state after reading the latest revision.

Commands

Command nodes store a command instance: commandId, optional commandVersion, and commandState. Executable command definitions are registry entries. Today the registry contains static commands, and the schema already leaves room for dynamic executable definitions later without changing node storage.
